Background

About Me

I work on the services behind applications and the data and infrastructure those services depend on.

How I build applications

Backend engineering is my main area of work. I build services in Go and Java, define how those services communicate, and connect them to databases and event pipelines. For a web application, that might mean designing a REST API that a React interface can call. Between backend services, I’ve used gRPC to define the information each service sends and receives.

I’ve also worked on the frontend. At Digit Healthcare, I helped integrate a React interface with services used in clinical workflows. At Verzeo, I contributed React and TypeScript features alongside transaction processing and data ingestion work. Working on both sides helps me see how API response times, data formats, and error messages affect the people using an application.

What I do on cloud and edge systems

At L&T Technology Services, I work with Vantiva on VIA, a platform that runs AI workloads across cloud and edge infrastructure. I develop Linux agent components that collect CPU, memory, disk, and network metrics directly from the host. The agents send structured metrics and batches of logs to cloud services, where Kafka helps process that operational data.

I’ve also implemented node health and capacity information used in model scheduling. When an AI model first loads, the additional startup time can affect how quickly a request completes. I added telemetry and monitoring so teams could see that delay and investigate it.

How I investigate performance issues

At Samsung, QA flagged a screen that took too long to load. I compared application and database timings and found that the service issued a database query for every record. I batched the reads, reviewed which indexes supported the query, and validated the change through automated tests and QA retesting.

At Digit Healthcare, I investigated a claims API that slowed down under peak traffic. After connection pool tuning gave temporary relief, I optimized a query that scanned excess data, removed repeated calls, and moved work that could run in the background to Kafka. Load tests and production monitoring helped verify how the system behaved under peak traffic.

My background in data science

I earned a Master of Science in Data Science from the University of North Texas. My capstone covered the full process of collecting and transforming streaming data, using it to train forecasting models, and communicating the results through interactive dashboards. The project gave me experience taking data from ingestion through analysis and presentation.

3. Present the results

I presented the analysis and forecasting results through interactive dashboards for technical and business audiences.
